## Corporate actions (raw facts, not synthesized trades)

Scope: every one of the 5188 panel STOCKS × integer operate-year 2018…2026 inclusive (2018 is a boundary control); indices excluded. Daily bars for all 5226 remain independently required. Priority: actual factor event years from complete SDK events and boundary years first, then fill remaining years. This priority is not proof of event absence: skipped years remain pending. For each pair explicitly request `query_dividend_data(dotted_code, year=str(year), yearType='operate')`, return code '0', correct fields, consume all pages; validate identity and `dividOperateDate` year. The exact ordered 14 columns are:

`code,dividPreNoticeDate,dividAgmPumDate,dividPlanAnnounceDate,dividPlanDate,dividRegistDate,dividOperateDate,dividPayDate,dividStockMarketDate,dividCashPsBeforeTax,dividCashPsAfterTax,dividStocksPs,dividCashStock,dividReserveToStockPs`

`dividend-queries/{undotted_code}/{YYYY}.json`: UTF-8, `source` exact above, `code` dotted, `year` four-digit STRING, `yearType` exact `operate`, `fields` ordered as above, `rows` an ordered array of 14 original strings per row with duplicates (no trim, rounding, numeric normalization or replacing missing with zero), `status` `queried` for nonempty fully consumed or `empty` only for actual error-free 0-row query. Keep failure attempts in append-only stage logs; do not write a success JSON on failure. `dividend-coverage.csv`: UTF-8 no BOM, LF, columns `code,year,status,rows,raw_path,raw_sha256,detail`; one row per expected pair, undotted code; `queried`/`empty` + real canonical path and SHA; `pending`/`failed` have NO trusted result and never qualify. No inferred empties. Extra out-of-panel facts, if present, must not enter this coverage grid. No independent confirmation from the lack of a factor change.

`dividend-events.csv`: same exact ordered 14 SDK fields, dotted codes and all values preserved as text, UTF-8 without BOM, CSV quoting, LF (including final line). Consume with dtype=str, keep_default_na=False. Include unique rows within the requested operate years (boundary controls included); downstream selects the simulation window explicitly. Integer-free conversion: use Decimal when interpreting numeric strings. Collapse completely identical 14-string tuples only; canonical key `(normalized lower undotted code, dividOperateDate)`; same key with a different original tuple is an unresolved conflict, not a revision chosen automatically. Sort by normalized code then ISO operate date. If contradictions remain, no official `READY.json`; keep raw evidence and diagnostic status. Never guess an event from adjusted-price changes, align a dividend to a nearby date, or use cash in place of shares. `query_dividend_data` alone does not provide a rights-subscription price/ratio or prove that all actions have been modelled.

Dates are exchange-local ISO `YYYY-MM-DD` or `''` (missing). Announcement dates are not registration/payment/listing dates. `dividRegistDate` is the close at which holdings establish entitlement, `dividOperateDate` ex-date, `dividPayDate` cash-available date, `dividStockMarketDate` bonus/capitalization share trading date: if required dates for that economic component are absent, do not invent settlement. `dividCashPsBeforeTax` is gross CNY/share; `dividCashPsAfterTax` can be a text interval and is not a definitive account-level net amount. `dividStocksPs` is bonus shares per original share (not total share distribution); `dividReserveToStockPs` capitalization shares/original share; retain separately. A clear plan can corroborate that an unreported component is inapplicable, but blank fields are never globally converted to zero; only demonstrably matching positive components and credible implementation dates support execution. Exclude unsupported rights, conflicting plans or unexplained price multiplier jumps from economic publication, not from the raw evidence. Check each observed in-window factor transition INCLUDING suspension and cross-year boundaries against independent implemented terms; do not infer funds or create raw shares by multiplying factors. Historical 2018 inputs are boundary checks, not positions owned before the simulation starts. A pure factor-only match or absent event provenance is not an accounting clearance.
